# 0003. リグ付き人体マネキンへの置換（方式B: スキンメッシュ + 回転リターゲット）

- ステータス: 採用
- 日付: 2026-07-18
- 関連: #12（親）, #22（実装）, #8（方式調査）, ADR 0002（方式Aを置換）

## 背景

方式A（手続き肉付け: カプセル + 球 + シリンダー）はプロダクションレベルの見た目に届かず、「ポーズリファレンスサイト（dessinpose.com 等）と同等の、人と分かるマネキン」への引き上げ要望を受けた（#22）。#8 の方式比較で方式Bの実現可能性を確認済み。

## 決定

**方式B（リグ付きヒューマノイド glTF + 回転リターゲット）** を採用し、方式Aの手続きマネキン（`mannequin.ts`）を置換・削除する。

- アセット: three.js examples の **Xbot.glb**（mixamorig スケルトン・グレーのマネキン風）を `public/models/mannequin.glb` に同梱。
- リターゲット: **自前 FK ソルバ**（`retarget.ts` + `skinnedMannequin.ts` の `applyPoseToSkeleton`）。階層順（Hips→Spine→Neck→四肢）に「子ボーンの現在ワールド方向 → landmark 目標方向」の回転を求め、親フレームに共役変換してローカル quaternion に premultiply する。Hips のみ骨盤基底（左右 hip × 体幹軸）の絶対姿勢を設定。
- 使用筋ヒート: スキンメッシュの **頂点カラー**で表現。頂点の支配ボーン（`skinIndex` の最大ウェイト）→筋群の対応表で着色し、大腿はバインド空間の前後（+Z 側=四頭筋 / −Z 側=ハムストリングス）、骨盤はバインド空間の左右 x 符号で L/R を判定する。`muscles.ts` の推定ロジック（`computeActivations` / `heatColor`）は変更しない。
- 凡例連携: 選択筋のハイライトは頂点カラーの再計算（非選択部位を中立色化）、ホバーは Raycaster の交差 face → 頂点 skinIndex → 筋群の逆引き（`musclesAtFace`）。
- カメラフィット: スキンメッシュは `Box3.setFromObject` で変形後を拾えないため、**ボーンのワールド座標群 + 0.15 パディング**で bbox を計算して `calculateCameraFit` に渡す。

## 検討した代替案

- **Kalidokit + three-vrm（VRM モデル）**: MediaPipe→VRM の実装が確立済みだが、VTuber 向け（正面直立中心）のチューニングでヨガの逆転・後屈への適応が不明、依存追加も増えるため不採用。自前ソルバは方向合わせのみの単純な数学で、任意ポーズに一様に振る舞う。
- **SMPL 系パラメトリックボディ**: research-only ライセンスのため不採用（#8）。
- **方式Aの改良（SDF/メタボール融合）**: 手・足・頭部の造形が困難で「人と分かる」水準に届かないため不採用。

## 前提（変えてよい / 壊すと危ない）

- **変えてよい**: アセット（mixamorig 互換スケルトンなら差し替え可。ボーン名は `mixamorig:` プレフィックス除去後のサフィックス一致で解決するため命名差異に耐性あり）、ヒート色域、カメラパディング。
- **壊すと危ない**:
  - `getVertexMuscleId` が返す筋 ID は `muscles.ts` の正典 ID（`MuscleId` + `:L/:R`、core のみ側なし）と一致させること。不一致だと ActivationMap 参照が silent に 0 になり全身が中立色になる（実際に踏んだバグ）。テストは正典 ID を import して検証する。
  - リターゲットのローカル変換は親フレーム共役（`parentWorldQ⁻¹ * q * parentWorldQ`）が必須。ワールド回転の直接 premultiply や「親のY軸=ボーン方向」の仮定は崩壊ポーズを生む（実際に踏んだバグ）。
  - 大腿前後・骨盤左右の判定は**バインドポーズ空間**で行うこと。ポーズ適用後のボーン位置や landmark 由来ベクトルと混ぜると向き依存で反転する。
- アセットのライセンス注記: Xbot は Mixamo 由来（three.js examples 同梱実績あり）。再配布に厳密を期す場合は CC0 アセットへの差し替えを検討（バックログ）。
