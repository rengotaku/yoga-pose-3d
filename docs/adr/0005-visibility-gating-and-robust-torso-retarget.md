# 0005. visibility ゲーティングとロバスト体幹リターゲット

- Status: Accepted
- Date: 2026-07-19
- Refs: #52（調査ログ・実測値）, #53, #54, #55, PR #56, #57, #58

## 背景

実画像 2 枚（後ろ向き膝立ち後屈+側屈 / 正面あぐら+胸前クロス+見上げ）で、2D 棒人間の見かけ精度低下と 3D マネキンの人体構造無視ポーズが再現された。実測により原因は以下と特定した（詳細は #52）。

1. MediaPipe の visibility を完全無視し、ハルシネーション座標（後ろ向き画像で脚 v=0.06〜0.4）を全信頼で描画・リターゲット・接地 IK に使用
2. Head ボーン未駆動（Neck の「肩中点→鼻」弦は頭部ピッチに不感）
3. 左右股関節の world 距離がオクルージョンで潰れ（実測 0.09m / 胴体長比 0.19）、hip line がノイズ支配になり骨盤が約 70° ロール
4. chord アラインのみで肩線の捻れ・傾き（側屈・捻転）が胴体に反映されない

## 決定

1. **visibility ゲーティング**（#53）: `RawLandmark` に visibility を保持し、しきい値を `VISIBILITY_GATE`（駆動 0.3 / IK 接地候補 0.5 / 2D 描画 0.3）に集約。未満はバインドポーズ維持・接地候補除外・非描画。visibility 欠損（undefined）は後方互換で可視扱い。床基準（最下点）は全候補から取り、接地分類のみ可視要求とする。
2. **頭部基底**（#54）: 「耳中点→鼻」を顔前方 Z、「右耳→左耳」を頭部左 X とする直交基底で Head の world 回転を絶対設定（Hips と同方式）。顔 landmark の visibility は後頭部でも 1.0 になるため、ゲートでなく幾何退化のみで無効化する。
3. **手駆動**（#54）: wrist→(INDEX+PINKY)/2 方向へ Hand ボーンを向ける。
4. **骨盤退化フォールバック**（#55）: hip距離/胴体長 < 0.35（`HIPS_BASIS`）で hip line を信頼せず「up × spine の水平ベクトル」を骨盤 X に使う。hip line の水平投影でないのは、spine chord が水平に近いポーズでは直交化で X が鉛直へ戻るため。符号は hip line（弱ければ肩線）の水平成分で決定。
5. **脊椎ツイスト**（#55）: 骨盤 X と実測肩線を spine 直交平面へ射影した角度差を spine 軸ツイスト（±60° クランプ、`SPINE_TWIST`）として Spine 3 ボーンへ分配。

## 検討して捨てた案

- **2D landmarks と world の融合**: 2D は画像空間で高精度だが、透視投影の逆算が必要で工事が大きい。効果不明のためバックログ化（#61 参照）。
- **顔 visibility による頭部ゲート**: 後頭部向きでも v=1.0 のため使用不能（実測で確認）。
- **肩線を骨盤 X のフォールバックに使う案**: 側屈時は肩線も傾いており骨盤には不適。
- **elbow/knee のヒンジ関節リミット**: visibility ゲーティングでガベージの大半が消えるため今回は見送り（バックログ #62）。

## 前提と注意（変えてよい前提 / 壊すと危ない前提）

- しきい値（0.3 / 0.5 / 0.35 / ±60°）は実画像 2 枚 + 代表 4 ポーズ（`make verify-poses`）での視覚検証による経験値。**調整してよいが、必ず両方の検証画像セットで再確認する**こと。
- Head/Hips の「world 回転絶対設定」は、同梱 glb（human-base）のボーン world 姿勢がバインド時にモデル空間基準（顔 +Z・上 +Y・左 +X）と一致している前提。**モデル差し替え時はこの前提が壊れうる**。
- visibility undefined を可視扱いにする後方互換は、既存テストフィクスチャと旧データのため。ゲートを厳格化するときはフィクスチャに visibility を付与してから。
