# 0006. 2D/world landmark 融合とヒンジ関節リミット

- Status: Accepted
- Date: 2026-07-19
- Refs: #61, #62, PR #64, #65（ADR 0005 の後続）

## 背景

ADR 0005 の visibility ゲーティングは、低 visibility landmark の world 座標がハルシネーションである問題を「駆動しない（バインドポーズ維持）」ことで回避した。しかし後ろ向き膝立ち側屈画像では脚全体が v=0.02〜0.26 でゲートされ、マネキンの脚が bind pose のまま水平に伸びる「板状破綻」が残った。一方、実測により同画像でも 2D landmarks（画像正規化座標）の x,y は正確（膝・足首が実際の膝立ち位置を指す）であることが確認された。

## 決定

1. **2D/world 融合**（#61, `fusion.ts`）: visibility ≥ 0.5 の anchor（6 点以上）で「回転なし similarity（等方スケール s + 並進 t）」を重み付き最小二乗フィットし、全 landmark の x,y を 2D 由来へ置換（z は world 維持）。anchor 不足・分散ゼロ・s ≤ 0 は world を**同一参照**で返す（呼び出し側はこの参照同一性で融合成立を判定する契約）。
2. **座標系は MediaPipe 系（y 下向き正）に統一**: MediaPipe は 2D も world も y 下向き正で、Three.js への反転は既存 `toVec`（x, −y, −z）が担う。fusion 内で y を反転すると**二重反転で上下逆**になる（実画像で確認した実装事故。中間座標は `v = y − 0.5`）。
3. **融合成立時の駆動ゲート緩和**（#61）: `applyPoseToSkeleton` へ `VISIBILITY_GATE.minDriveFused = 0` を渡し、低 visibility の四肢も fused x,y で駆動する。IK 接地（0.5）・2D 描画（0.3）のゲートは維持。
4. **ヒンジ関節リミット**（#62, `jointLimits.ts`）: retarget/IK/筋推定への入力前に landmark 空間でサニタイズする。膝は骨盤前方軸（hips 基底 +Z を大腿に直交化）への逆曲がりをミラー反転（deadband 下腿長比 0.05）+ 屈曲 150° クランプ。肘は屈曲 150° クランプのみ。visibility ゲートは駆動ゲートと同値を渡して「駆動されるのにクランプされない」部位を防ぐ。

## 検討して捨てた案

- **融合に回転項を入れる**: 静止画のヨガ写真はカメラほぼ正立で、回転自由度はノイズを吸収して劣化要因になる。
- **肘の逆曲がりミラー**: 肘のヒンジ軸は上腕の内外旋に追従し landmark から観測できないため、骨盤/胴体前方を参照するミラーは正しいポーズ（頭上・背面の腕）を壊すリスクの方が高い。
- **#55 骨盤退化フォールバックの置き換え**: #61 起票時は「融合が入れば置き換えられる可能性」とされていたが、**側面視では左右股関節が画像上で重なるため 2D 由来の hip 距離は world よりさらに潰れる**（実測: 側屈画像で fused hip 距離比 0.08）。フォールバックは融合後も必須の安全網として存続。

## 前提と注意（変えてよい前提 / 壊すと危ない前提）

- しきい値（anchor 0.5 / 6 点、deadband 0.05、屈曲 150°）は実画像 2 枚 + 回帰 9 ポーズの視覚検証による経験値。**調整してよいが両セットで再確認する**こと。膝屈曲 150° はあぐら・正座の深い折りたたみをわずかに開かせる副作用が既知（#66）。
- `fuseLandmarks` のフォールバック同一参照契約は `PoseViewer3D` の融合成立判定が依存する。**コピーを返すよう変えると駆動ゲート緩和が誤作動する**。
- fusion / jointLimits の出力は MediaPipe 系（y 下向き正）のまま。**Three.js 系へ変換した値を landmark 配列へ混ぜてはいけない**（反転は toVec に一元化）。
