# 0002. 肉付き筋肉ボディと使用筋ヒートマップ（方式A: 手続き肉付け）

- ステータス: 採用
- 日付: 2026-07-18
- 関連: #1（親）, #8（解剖レイヤ調査）

## 背景

MVP の 3Dビューアは球＋シリンダーの簡易骨格（棒人間）だった。Muscle & Motion のように「肉付きの筋肉ボディ」で表示し、かつ「どの筋肉が使われているか」を可視化したいという要望を受けた。

## 決定

**方式A（手続き肉付け）** を採用する。

- 既存の `worldLandmarks`（MediaPipe 33 点）から、肢体を筋肉状カプセル、胴体をシリンダーメッシュで手続き生成する。
- 関節角度・分節ベクトルから 8 筋群のアクティベーション（0..1）を**幾何学的にヒューリスティック推定**し、部位をヒートマップ（ベージュ→オレンジ→赤）で着色する。使用筋は 3Dビュー下部の凡例にも一覧する。

## 検討した代替案

- **方式B: リグ付き解剖モデル（SMPL 等 + 筋メッシュ）**。M&M に最も近いが、(1) SMPL 系はライセンス制約、(2) landmark→bone のリターゲット実装が重い、(3) アセット調達コスト。MVP 段階では過剰。
- **方式C: OpenSim/筋骨格シミュレーションの web export**。GPU/計算コストとブラウザ動作の不確実性が高い。

## 前提（変えてよい / 壊すと危ない）

- **変えてよい**: 筋群の推定係数・ヒート色域・カプセル半径・凡例レイアウト。
- **壊すと危ない**: 使用筋は EMG 実測ではなく幾何推定という位置づけ（UI にも明記）。ここを「実測」と誤表示すると意味が変わる。
- 座標変換 `(x, -y, -z)`（`muscles.ts` の `toVec`）は 2D オーバーレイ・カメラ設定と整合しているため、変更時は描画全体を再確認する。

## 次アクション

- 方式B（個別筋の分離・前後での色替え等、より解剖学的な忠実度）は enhancement として #8 系列で継続検討する。
