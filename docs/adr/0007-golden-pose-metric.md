# ADR 0007: ゴールデンポーズ指標による再現精度の定量化

## ステータス

採用（#71 / #72）

## 背景

3D マネキンのポーズ再現精度はユーザー体感で 60% 程度だが、総合精度を測る指標が
存在せず、改善が収束しているか判定できなかった。改善履歴（#35 後屈、#54 頭部、
#55 脊椎、#61 融合、#62 関節リミット）はすべて症状ベースで、目標値が無い。

## 決定

1. **ゴールデン = 手付けのボーン回転 JSON**（`e2e/golden/<pose>.json`）
   - キーは mixamorig 標準名（`BONE_ALIASES` のキー）、値はバインドポーズからの
     相対 Euler 回転（XYZ オーダー、度）
   - リターゲットパイプラインを一切通さず `applyGoldenRotations` で直接適用する。
     「パイプラインがどうあるべきだったか」の正解を、パイプラインと独立に定義する
2. **スコア = world 回転の角度差の重み付き平均**（`scorePose`）
   - 対象はリターゲットが駆動する 15 ボーン（`SCORE_BONE_WEIGHTS`）。
     foot/ball/clavicle は駆動対象外のため除外
   - **ローカルでなく world 回転**を比較する。spine 3 分配のような「合計は同じで
     配分が違う」実装差をペナルティにせず、見た目の向きのズレだけを測るため
   - 関節スコア = max(0, 1 − 角度差/90°)。90° ズレで 0 点の線形減点
   - 重みは見た目への寄与の主観設計: Hips 2.0 > UpLeg/Arm 1.5 > Leg/ForeArm 1.25
     > Spine×3/Head 1.0 > Hand 0.5
3. **実写真はコミットしない**: ゴールデンの元になる実写真（動画スクショ等）は
   著作権配慮でローカル参照のみ（`sources.local.json`、gitignore の `*.local` で
   除外）。コミットするのはゴールデン JSON と自前レンダー（CC0 モデル）のみ。
   このため `make pose-score` はローカル実行前提で CI に含めない
   （`make verify-poses` と同じ扱い）
4. **dev 専用 window フック**（`window.__poseDebug`）で e2e スクリプトから
   適用・エクスポート・採点を行う。`import.meta.env.DEV` ガードで本番バンドル
   には含めない

## 検討して捨てた案

- **スクリーンショットの画像類似度（SSIM 等）で採点**: カメラ・ライティング・
  メッシュ差に敏感で、関節ごとの欠陥リストに分解できないため不採用
- **landmark 座標の距離で採点**: パイプライン入力（MediaPipe 出力）の誤差と
  リターゲットの誤差を分離できないため不採用。ゴールデンをボーン回転で持てば
  「入力が同じでも到達すべき姿勢」を直接定義できる
- **ローカル回転の比較**: 誤差の親子間配分の違いを過剰にペナルティ化するため
  world 回転を採用

## 変えてよい前提 / 壊すと危ない前提

- 重み・90° 線形減点は初期値であり、運用（ユーザー体感との乖離）に応じて調整
  してよい。ただし**調整したら過去スコアと比較不能になる**ため、変更時は
  ADR 追記と全ポーズ再計測をセットにする
- ゴールデン JSON は「バインドポーズからの相対回転」前提。マネキン glb を
  差し替えてバインドポーズが変わると全ゴールデンが無効になる（作り直し）
- `__poseDebug` は dev 専用契約。テスト・e2e 以外のアプリコードから参照しない
